# 0006. RDB 스냅샷: fork + COW, 자체 포맷, 손상 시 기동 거부

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
SAVE/BGSAVE로 전체 키스페이스를 저장하고 기동 시 로드해야 한다. BGSAVE 중에도 서비스는 멈추면 안 된다.
손상된 파일을 조용히 빈 DB로 넘기면 데이터 유실을 가린다.

## 결정
- BGSAVE는 `fork()`한 자식이 fork 시점 스냅샷을 쓰고, 부모는 계속 서비스한다.
- 포맷은 자체 바이너리(`MRDB` 매직, 버전 1)에 전체 바이트의 64비트 rolling checksum footer를 붙인다. 만료 시각도 저장하고 로드 시 이미 만료된 키는 버린다.
- 임시 파일(`<path>.tmp-<pid>`)에 쓴 뒤 `rename()`한다.
- 체크섬이나 구조 검사가 실패하면 기동을 거부한다(비0 종료). 파일이 없으면 빈 DB로 기동한다.

## 대안
- 잠금을 건 직렬화, 저장 스레드: 단일 스레드 제약과 맞지 않고 잠금이 필요하다.
- 원본 파일에 바로 쓰기: 쓰다 실패하면 기존 스냅샷도 잃는다.
- 경고 후 빈 DB로 기동: 데이터 유실을 가린다.
- 진짜 RDB 포맷 호환: 범위 밖이다.

## 결과
- 장점: 잠금 없이 일관된 스냅샷을 얻는다. 체크섬이 구조 검사가 놓친 손상도 잡는다.
- 단점/감수한 점: 진짜 Redis의 RDB 파일과 호환되지 않는다.
