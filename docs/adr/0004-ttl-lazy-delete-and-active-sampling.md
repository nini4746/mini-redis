# 0004. TTL: 별도 만료 테이블, 지연 삭제, 주기 샘플링

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
만료 시각이 지난 키가 GET에서 값을 반환하면 안 된다. 접근이 없는 만료 키도 결국 지워져야 한다.
진짜 Redis 방식을 모사하는 것이 학습 목표다.

## 결정
- 만료 시각은 `robj`가 아닌 별도 dict(`expires`)에 둔다.
- 만료 검사는 `lookup` 한 곳에서 한다 (지연 삭제).
- 이벤트 루프 100ms 틱마다 만료 테이블에서 무작위 20개를 뽑아 만료분을 지운다. 만료 비율이 25%를 넘으면 반복하되, 최대 16회와 25ms로 제한한다.

## 대안
- `robj`에 만료 필드: 주기 샘플링이 만료가 있는 키만 뽑을 수 없다.
- 전수 스캔, 키별 타이머: 키 수에 비례하는 비용이 든다.
- 명령마다 만료 검사: 우회 경로가 생길 수 있다.

## 결과
- 장점: 상수 비용으로 만료를 처리하고, 만료 키가 값으로 보이는 경로가 없다.
- 단점/감수한 점: 접근이 없는 만료 키는 샘플링에 걸릴 때까지 메모리에 남는다.
