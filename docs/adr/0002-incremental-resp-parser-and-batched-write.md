# 0002. 재파싱 방식 incremental RESP2 파서와 응답 일괄 write

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
한 요청이 여러 `read()`로 쪼개져 오거나(부분 수신), 한 `read()`에 여러 요청이 몰려 온다(파이프라이닝).
파이프라인 응답 순서는 요청 순서와 같아야 한다.

## 결정
- 파서는 명령 하나를 끝까지 파싱해 커밋하기 전까지 rbuf를 건드리지 않는다. 입력이 불완전하면 다음 수신 후 처음부터 다시 파싱한다.
- 응답은 클라이언트 버퍼에 모아 한 번에 `write()`한다.

## 대안
- 파서 상태 기계 저장: 상태를 들고 다녀야 해 복잡하다.
- 명령마다 `write()`: 파이프라이닝에서 syscall과 왕복 비용을 상각하지 못한다.

## 결과
- 장점: 부분 수신과 파이프라이닝을 같은 루프로 처리한다. `BENCH.md`에서 `-P 16`은 `-P 1` 대비 약 10~13배 처리량이다.
- 단점/감수한 점: 입력이 불완전하면 수신할 때마다 같은 지점부터 다시 파싱한다.
